# 機車銷售與維修分紅設計

日期：2026-10-17
狀態：待使用者審閱；尚未實作、Commit 或部署

## 目的與範圍

店長希望以固定、可追溯的規則計算兩種分紅：機車銷售給統一名單內每位業務員同額獎金；維修完工給該單唯一維修人員按扣除零件成本後的淨額抽成。店長能設定及查看金額，一般員工只能完成原有銷售和維修流程，不得看到分紅。第一版只處理功能啟用後的新交易，不回算舊單，也不新增完工後退回功能。

## 已確認的業務規則

1. 店長在品項上設定「適用機車獎金」，不以品項分類文字判斷。全店共用一個每台機車獎金金額；店長維護一份可領此獎金的業務員名單。結帳時，每筆適用品項依售出數量計算，名單內每位業務員都得到相同金額；不用逐單指定獎金對象。既有銷售歸屬業務員仍供原有月銷售績效使用，與這份獎金名單是不同概念。
2. 維修人員使用獨立名單，不與業務員或登入帳號混用。每張維修單只能指定一位維修人員；沒有指定時不能確認完工。一般員工可從有效名單中指定並確認完工，店長維護名單。
3. 店長設定全店共用的維修分紅百分比。維修單確認完工時，依 `max(維修單金額 − 實際使用零件的成本, 0) × 分紅百分比` 計算唯一維修人員的分紅。維修單金額包含該單既有的工資與用料售價；成本只含實際使用零件、用品或電池的成本，不扣其他費用。淨額為零或負數時不發分紅；不等收款才計入。
4. 設定變更只影響之後成立的分紅。已成立紀錄保存當時的金額、百分比、品項數量、成本及領取對象，不能因後來修改費率、名單、品項標記或成本價而重算。
5. 現有流程只能取消未完工維修單，不能退回已完工維修單。第一版不新增完工後退回或單獨沖回按鈕。日後若加入正式退回流程，庫存、保固及分紅須在同一交易中處理沖回，並保留原紀錄及沖回紀錄。
6. 第一版不回算舊單。機車獎金金額未設定、符合資格名單為空，或維修分紅百分比未設定時，不建立分紅紀錄；設定為零視為明確不發。前端須清楚顯示設定狀態，避免把「未設定」誤認為計算成功。

## 方案選擇

選用「交易成立時記帳」：在現有結帳與確認完工的資料庫交易內建立不可直接編修的分紅紀錄及計算快照。這能保留歷史費率、避免重複結帳產生重複分紅，且將來能以反向紀錄沖回。未選用「開報表時依目前設定動態重算」，因為設定變更會改變舊單金額，也難以核對沖回。

## 元件與資料流

- 店長設定：保存每台機車獎金、維修分紅百分比、機車獎金適用品項標記、業務員獎金名單及獨立維修人員名單。設定與分紅金額只經店長專用資料庫操作讀寫；一般員工可讀有效維修人員姓名以供維修單選擇，但不可讀獎金設定或紀錄。
- 機車結帳：沿用現有銷售建立 RPC，在同一資料庫交易內找出已標記的銷售行項，依數量乘以當時每台獎金，為名單內每位業務員各寫一筆分紅快照。以銷售單與受領業務員設唯一約束，重試同一結帳不得重複記帳。銷售歸屬欄位及既有月銷售績效保持原樣。
- 維修保存與完工：維修單保存一位維修人員 ID；完工 RPC 鎖定維修單及要扣料的品項，驗證維修人員仍有效並逐行取得成本，以 `數量 × 單位成本` 加總，在扣庫存、建立保固及設定完工狀態的同一交易內寫入維修分紅快照。第一版以品項在完工當下登錄的單位成本作為用料成本並保存快照；現有資料沒有將每件用料連回特定進貨批次，因此這不是逐批次的實際採購成本。成本資料缺失時拒絕完工並提示先補齊成本；成本為明確的 0 則可計算。每張維修單至多一筆原始維修分紅；零分紅可不建獎金紀錄，但計算結果須可供店長核對。
- 報表：店長專用頁面按月份顯示機車與維修分紅、個人合計及原始單號，金額由已記帳快照加總，不以目前設定重算。月份以台灣時間的結帳／完工日期歸屬。一般員工即使直接呼叫資料 API 也不能取得分紅明細與設定。

## 錯誤、安全與一致性

- 只在資料庫端計算並寫入獎金；前端預覽值不作為記帳依據。資料庫權限需沿用現有 `profiles` 的店長／員工判定，不能僅靠隱藏按鈕保護金額。私有表與 RPC 要限制讀寫權限、保留 RLS，避免跨角色讀取或直接改寫快照。
- 金額使用 PostgreSQL `numeric`，獎金四捨五入至小數兩位；明確限制獎金及百分比非負，百分比不超過 100%。業務員或維修人員停用後，舊分紅仍保留姓名快照；新交易只使用有效名單。
- 若結帳、扣料、保固或分紅寫入任一步失敗，整筆交易回滾，不能留下已成交但沒記到應發獎金、或已完工卻未扣料的部分結果。現有未提交的 `docs/performance-audit.md` 不屬於本功能，不修改。

## 預計影響範圍與驗收

- 資料庫：新增獎金設定／名單／快照及維修人員資料結構；延伸品項標記、維修單的維修人員欄位、既有結帳與維修完工 RPC；增加店長專用查詢與必要索引／權限。實際 migration 名稱和 SQL 在實作計畫中確認。
- 前端：`index.html`、`app.js`、`cloud-data.js`、`repair-ui.js`，必要時含 `style.css`；沿用目前原生 JavaScript 和頁面切換方式，避免另建框架。
- 測試：新增／延伸 `supabase/tests` 的銷售與維修 SQL 測試，以及相關前端測試，涵蓋每台乘數、多人同額、未設定或零額、淨額非正、成本快照、無維修人員拒絕完工、重試不重複、停用人員、舊資料不回算、店長／一般員工權限、交易失敗回滾。
- 驗收：店長能設定及查看分紅；一般員工看不到金額但可指定維修人員；一次結帳／完工只產生正確的一次分紅；改設定不改舊紀錄；未完成資料庫變更或部署前，不宣稱正式站已啟用。

## 第一版刻意不做

不做按車款不同獎金、逐單指定銷售獎金對象、多人分攤維修分紅、待收款才計入、舊單回算、獎金實際發薪或付款、完工後退回與退款。這些若日後加入，需另定規則與測試。

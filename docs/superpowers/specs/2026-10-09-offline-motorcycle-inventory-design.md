# 離線微型機車店庫存系統：設計規格

## 目標與範圍

建立一個供單一店員在單一電腦離線使用的瀏覽器庫存系統。資料必須在關閉頁面後保留，且使用者能自行匯出及還原資料備份。

第一版包含：

- 管理機車、零件與用品品項。
- 進貨、售出與盤點調整庫存，並保留異動紀錄。
- 顯示低庫存提示與近期異動。
- 匯出完整 JSON 備份與匯入已驗證的 JSON 備份。

第一版不包含：帳號、多人同步、雲端資料庫、條碼掃描、採購單、多店管理或報表。

## 技術與檔案結構

系統以純 HTML、CSS 與 JavaScript 製作，無建置步驟、無外部套件、無網路依賴。使用者以瀏覽器直接開啟 `index.html` 即可使用。

- `index.html`：畫面結構與對話框。
- `style.css`：響應式與無障礙樣式。
- `app.js`：資料存取、驗證、畫面渲染與操作事件。

資料只使用同一瀏覽器來源的 `localStorage`，鍵名固定為 `motorcycleInventory`。若使用無痕視窗或清除網站資料，記錄會消失；介面必須提供可下載的備份檔。

## 資料模型

儲存值為一個 JSON 物件：

```json
{
  "items": [
    {
      "id": "uuid",
      "name": "前煞車皮",
      "category": "零件",
      "sku": "BRK-001",
      "cost": 180,
      "price": 350,
      "stock": 8,
      "minimumStock": 3,
      "notes": ""
    }
  ],
  "transactions": [
    {
      "id": "uuid",
      "itemId": "uuid",
      "type": "in",
      "quantity": 4,
      "createdAt": "2026-10-09T00:00:00.000Z",
      "note": "到貨"
    }
  ]
}
```

品項的 `name` 必填；`category` 限為「機車」、「零件」或「用品」；`sku` 可留空；成本、售價、庫存與最低庫存為零或正數。異動類型限為 `in`（進貨）、`out`（售出）與 `adjust`（盤點後設定庫存）。

## 使用流程

### 儀表板

首頁顯示品項數、總庫存數、低庫存品項清單，以及最近十筆異動。低庫存定義為 `stock <= minimumStock`。

### 品項管理

庫存頁可依名稱、料號或分類搜尋；可新增及編輯品項。刪除前必須要求確認，並同時移除該品項的異動紀錄，以避免留下無法對應的資料。

### 庫存異動

店員選擇品項、異動類型、數量與選填備註後送出。進貨使庫存增加，售出使庫存減少，盤點調整將庫存設為輸入值。售出若會使庫存低於零，系統拒絕該筆異動並顯示原因。

### 備份與還原

匯出會下載完整資料物件的 JSON 檔。匯入必須先解析、驗證資料結構與每個欄位，再讓使用者確認覆蓋目前資料；驗證失敗或取消時不得寫入資料。

## 錯誤處理與無障礙

所有表單欄位在送出時驗證，錯誤訊息需在對應欄位附近以文字呈現，且不可只用顏色傳達。危險操作（刪除、匯入覆蓋）均需明確確認。按鈕、輸入欄與對話框均可用鍵盤操作並有可辨識標籤。

若 `localStorage` 寫入失敗，系統顯示無法儲存的訊息，且不宣稱操作已完成。若載入資料失敗，系統保留原始資料而不自動覆寫，並要求使用者以匯入備份復原。

## 驗證策略

在瀏覽器主控台可執行的內建斷言會驗證：

1. 進貨、售出與盤點調整後的庫存值。
2. 超賣被拒絕且庫存保持不變。
3. 不合法的品項與備份資料被拒絕。
4. 匯出後再匯入可保留品項與異動紀錄。

另以手動驗證檢查新增、搜尋、編輯、刪除確認、低庫存顯示、備份下載與還原流程。

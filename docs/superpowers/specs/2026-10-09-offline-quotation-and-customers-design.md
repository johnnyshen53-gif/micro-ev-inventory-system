# 離線客戶與報價系統設計

**日期：** 2026-10-09  
**範圍：** 微型機車店庫存系統第一版的客戶與報價功能

## 目標與限制

單一店員在一台電腦、無網路的環境下，管理客戶並建立可重複查閱及列印的報價單。資料只存於瀏覽器，且必須與既有庫存、條碼掃描和 JSON 備份共存。

報價採品項的標準售價；不允許在報價單上改價或折扣。建立或列印報價都不會保留、扣除或調整庫存。

## 資料模型

整體狀態由既有的 `items`、`transactions` 擴充為：

```js
{
  items: [],
  transactions: [],
  customers: [],
  quotations: []
}
```

### 客戶

```js
{
  id, name, phone, note, active, createdAt, updatedAt
}
```

- `name` 和 `phone` 為必填字串；電話可重複。
- `note` 為選填字串。
- 新客戶的 `active` 為 `true`。
- 停用客戶設為 `active: false`：不出現在新建報價的選單，歷史報價仍可顯示。

### 報價單

```js
{
  id, number, customerId, customerName, customerPhone,
  lines: [{ itemId, itemName, quantity, unitPrice, subtotal }],
  total, note, createdAt
}
```

- `number` 為建立時產生、不可變更的人可讀報價編號。
- 客戶名稱和電話會複製到報價單，讓客戶資料日後被編輯或停用時，歷史單據仍保持原樣。
- 每筆明細會複製品項名稱及當下的標準售價；`subtotal = quantity * unitPrice`，`total` 為所有小計的總和。
- 報價建立後為唯讀且不可刪除；第一版不支援編輯、轉售出或取消還原。

## 頁面與使用流程

系統只使用一個 `index.html` 入口。上方頁籤以原生按鈕在同一份 HTML 中切換內容區塊，不改變網址；`[hidden] { display: none !important; }` 保證切換在 `file://` 環境下也正確隱藏非當前區塊。

1. **庫存清單頁籤**：顯示總覽、低庫存、近期異動和品項清單。
2. **庫存管理頁籤**：建立或編輯品項、使用條碼掃描選品並登記庫存異動。
3. **客戶管理頁籤**：建立、編輯、搜尋客戶；可停用客戶。已有報價的客戶不能永久刪除。
4. **報價單頁籤**：選擇有效客戶；反覆加入現有庫存品項與正整數數量；畫面即時計算小計和總額；下方提供報價紀錄搜尋、檢視明細與再次列印。
5. **列印視圖**：使用瀏覽器原生列印對話框，顯示店名標題、報價編號、日期、客戶姓名／電話、品項明細、總額與備註；螢幕控制項不印出。使用者可列印紙本或另存 PDF。

## 規則與錯誤處理

- 新建客戶：姓名與電話不可為空白。
- 新建報價：必須選擇有效客戶，且至少有一筆明細；每筆數量必須是大於零的整數。
- 新建報價只能選擇現有庫存品項，但不要求庫存數量足夠；選單同時顯示目前庫存，提醒店員報價不等於保留貨品。
- 報價明細不允許手動更改單價、折扣或小計。
- 若品項已有報價紀錄，將不可刪除；歷史報價與品項資料都保留。
- 驗證失敗時不寫入 LocalStorage，並在對應表單顯示清楚錯誤。

## 備份與相容性

- 匯出 JSON 包含 `customers` 與 `quotations`。
- 匯入舊版資料時，若沒有兩個新陣列，視為空陣列並正常匯入。
- 匯入時驗證所有 ID 唯一、明細金額正確、客戶與品項關聯存在；任一不合法即拒絕整份匯入，保留目前資料。

## 介面準則

- 延續既有扁平、易讀、資料密集但不擁擠的營運工具風格。
- 表單使用清楚的標籤、鍵盤可操作的原生控制項、可見焦點與欄位內錯誤。
- 報價列表優先呈現編號、日期、客戶與總額；報價頁籤優先呈現客戶、明細和合計。
- 列印 CSS 將互動控制項、導覽與非必要區塊隱藏，只保留單據內容。

## 驗證策略

自動測試應覆蓋：

- 客戶新增、編輯、停用與必填驗證。
- 報價總額計算、價格／名稱／客戶資訊快照與不可用客戶／品項拒絕。
- 報價建立不影響庫存或異動紀錄。
- 舊備份匯入與新資料匯出／匯入。
- 現有庫存與條碼測試持續通過。
- HTML 靜態檢查：單頁有四個頁籤與對應內容區塊、列印內容包含必要欄位，並且不使用 `type=module`。

手動驗證應確認：建立客戶、建立報價、列印預覽／另存 PDF、歷史報價重印，以及客戶或品項停用後的歷史顯示。

## 明確排除項目

- 報價改價、折扣、稅金、有效期限、付款條件與簽名。
- 將報價轉成售出、庫存保留、庫存不足的預留處理。
- 多使用者、雲端同步、客戶去重與相機掃描。
